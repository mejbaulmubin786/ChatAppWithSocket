## এবার আমরা এডমিন ড্যাসবোর্ড এর কিছু কাস্টমাইজ করবো । আমরা প্রথমে সাইডবার নিয়ে শুরু করি । যেহেতু আমরা প্রথমেই আমাদের মুল থিমকে পার্ট বাই পার্ট আলাদা করে ফেলেছি তাই সাইডবার পরিবর্তর্ন এর জন্য সাইডবার পেইজে যাবো।

```php
<div>
    <h4 class="logo-text">Admin</h4>
</div>
```

চাইলে প্রথমে এখানে Admin লিখতে পারি এর পরে আমাদের থিমে যে Dashboard মেনু আছে এটি একটি ড্রপ ডাউন মেনু আমরা চাই না এটি ড্রপ ডাউন থাকুন। আবার আমাদের Widgets টা ও দরকার নেই।

```php
<li>
    <a href="widgets.html">
        <div class="parent-icon"><i class='bx bx-cookie'></i>
        </div>
        <div class="menu-title">Widgets</div>
    </a>
</li>

```

তাই এটিকে কাট করে লিস্ট এর একদম উপরে পেস্ট করে দিবো Widgets পরিবর্তন করে নাম দিবো Dashboard আর পূর্বের Dashboard মেনুকে নাম দিবো Brand। এখন আমরা চাই যে Dashboard এ ক্লিক করলে যেন যেখানেই থাকুক না কেন Dashboard আসা যায় তাই এখানে `widgets.html` এর পরিবর্তে ডাইনামিক রাউট `{{ route('admin/dashboard') }}` যুক্ত করে দি। কারণ এর জন্য আমরা
রাউট যখন এভাবে ডিফাইন করেছি:

```php
Route::get('/admin/dashboard', [AdminController::class, 'AdminDashboard'])->name('admin.dashboard');
```

### ব্যাখ্যা।

এখানে `.name('admin.dashboard')` অংশটি একটি **নেমড রাউট** (named route) তৈরি করে। নেমড রাউট ব্যবহারের সুবিধা হলো, আপনাকে সরাসরি URL লিখতে হয় না, বরং আপনি সহজেই রাউটের নাম দিয়ে এটি অ্যাক্সেস করতে পারেন। ম্যানুয়াল URL ব্যবহার (যদি খুব জরুরি হয়): {{ url('/admin/dashboard') }} বা শুধু {{ '/admin/dashboard' }} ব্যবহার করা যায়।

Laravel-এ **`{{ url('/admin/dashboard') }}`** এবং **`{{ '/admin/dashboard' }}`** দুটিই কাজ করবে, তবে এগুলোর মধ্যে পার্থক্য এবং **সঠিক পদ্ধতি** বিবেচনায় `{{ url('/admin/dashboard') }}` ব্যবহারের পরামর্শ দেওয়া হয়।

### তুলনা এবং বিশ্লেষণ

#### 1. **`{{ '/admin/dashboard' }}`**

-   **কাজ করার ধরন:**
    এটি একটি **স্ট্যাটিক URL**, যা সরাসরি `/admin/dashboard` স্ট্রিং হিসেবে আউটপুট দেয়।
-   **সুবিধা:**
    -   সহজ এবং সরাসরি লেখা যায়।
    -   কোনো অতিরিক্ত প্রসেসিং প্রয়োজন নেই।
-   **অসুবিধা:**
    -   **বেস URL** বা ডোমেইনের ওপর নির্ভরশীল নয়। যদি আপনি সাবডোমেইন বা কাস্টম ডোমেইন যোগ করেন, এটি সেই পরিবর্তনগুলি গ্রহণ করতে পারবে না।
    -   ভবিষ্যতে রাউট পরিবর্তন হলে এই URL-টি ম্যানুয়ালি খুঁজে খুঁজে সংশোধন করতে হবে।
    -   Laravel-এর বিল্ট-ইন সুবিধা ব্যবহার করে না।

---

#### 2. **`{{ url('/admin/dashboard') }}`**

-   **কাজ করার ধরন:**
    -   Laravel-এর **`url()` হেলপার ফাংশন** ব্যবহার করে URL তৈরি করে।
    -   এটি **বেস URL** (যেমন `http://yourdomain.com`) স্বয়ংক্রিয়ভাবে যুক্ত করে।
-   **সুবিধা:**
    -   ডাইনামিক URL তৈরি করে, যা ডোমেইন বা অ্যাপ্লিকেশন রুট পরিবর্তনের সঙ্গে মানিয়ে নেয়।
    -   কাস্টম সাবডোমেইন বা ডোমেইনের ক্ষেত্রে সঠিক URL রিটার্ন করে।
    -   Laravel-এর সিস্টেমের সঙ্গে সামঞ্জস্যপূর্ণ এবং ফিউচার-প্রুফ।
-   **অসুবিধা:**
    -   একটু বেশি কোড লাগে (তবে এতে কোনো কার্যক্ষমতার সমস্যা নেই)।

---

### উদাহরণ

#### ক) সরাসরি লেখা (স্ট্যাটিক):

```php
<a href="{{ '/admin/dashboard' }}">Dashboard</a>
```

আউটপুট:

```
/admin/dashboard
```

#### খ) Laravel-এর `url()` ফাংশন ব্যবহার:

```php
<a href="{{ url('/admin/dashboard') }}">Dashboard</a>
```

আউটপুট:

```
http://yourdomain.com/admin/dashboard
```

### কোনটি সঠিক পদ্ধতি?

-   যদি Laravel-এর ডাইনামিক, স্কেলেবল এবং ফিউচার-প্রুফ অ্যাপ্লিকেশন তৈরি করতে চান, তাহলে **`{{ url('/admin/dashboard') }}`** ব্যবহার করা সঠিক পদ্ধতি।
-   শুধু **`{{ '/admin/dashboard' }}`** তখনই ব্যবহার করুন, যখন আপনি নিশ্চিত যে বেস URL বা ডোমেইন কখনো পরিবর্তন হবে না (যা প্রায় অসম্ভব)।

---

### সারাংশ:

Laravel-এ **`url()` হেলপার ফাংশন** ব্যবহার করার অভ্যাস গড়ে তুলুন। এটি পেশাদার এবং দীর্ঘমেয়াদে কার্যকর পদ্ধতি।

-   **সঠিক পদ্ধতি:** `{{ url('/admin/dashboard') }}`
-   **বেশি ভালো পদ্ধতি:** যদি নেমড রাউট থাকে, তাহলে `{{ route('admin.dashboard') }}` ব্যবহার করুন।

### এবার সাইড মেনু থেকে অপ্রয়োজনিয় অনেক গুলো মেনু বাদ দিয়ে দিলাম। এবার থিম এর মেইন পার্ট থেকে অপ্রয়োজনিয় অংশ গুলো বাদ দিবো এর জন্য যেতে হবে index পেইজে কারণ মেইন অংশ সেখানেই আছে।

### এবার আমরা ডেসবোর্ড এর হেডার এরিয়াতে দেখবো এখানে স্টেটিক ডাটা আছে আমরা যদি চাই এখানে ডাইনামিক ডাটা থাকুক যাতে ডাইনামিক্যালি তথ্য আছে । আমরা যখন ব্রিজ এর ডিফল্ট ড্যাসবোর্ড এ লগিং করে ছিলাম তখন সেখানে আমরা ই্জার না এডমিন না ভেন্ডর তার তথ্য দিতো। আমরা যখন resources/views/layouts এর ভেতর navigation পেইজে যাই সেখানে `<div>{{ Auth::user()->name }}</div>` এই অংশ টুকু পাই

### কোর্ড ব্যাখ্যা

**কোড:**

```php
<div>{{ Auth::user()->name }}</div>
```

### এই কোডে কী হচ্ছে?

১. **`Auth` ফ্যাসাড:**

-   এটি লারাভেলের একটি বিল্ট-ইন ক্লাস (ফ্যাসাড), যা **অথেনটিকেশন সিস্টেম** পরিচালনা করে।
-   এটি ব্যবহার করে আপনি জানতে পারেন কোন ইউজার লগইন করেছেন বা সেশনে আছেন।

২. **`user()` মেথড:**

-   `Auth::user()` ফাংশনটি সেই ইউজারের তথ্য রিটার্ন করে, যিনি বর্তমানে **লগইন করেছেন**।
-   উদাহরণ: এটি ইউজারের নাম, ইমেইল, বা অন্য যেকোনো তথ্য (যা ডাটাবেজে সংরক্ষিত) রিটার্ন করতে পারে।

৩. **`name` প্রপার্টি:**

-   `Auth::user()->name` বলতে এখানে `user()` মেথড থেকে পাওয়া **ইউজারের অবজেক্টের** মধ্যে থাকা `name` ফিল্ডটি বোঝানো হয়েছে।
-   অর্থাৎ, এটি সেই ইউজারের **নাম** দেখাবে যিনি লগইন করেছেন।

৪. **`{{ }}` (Blade Syntax):**

-   লারাভেলের টেমপ্লেট ইঞ্জিনের নাম হলো **Blade**।
-   `{{ }}` ব্যবহার করে PHP কোডকে HTML এর মধ্যে **রেন্ডার** করা হয়।

### কোডের আউটপুট কেমন হবে?

ধরা যাক, আপনার ডাটাবেজে একটি ইউজারের নাম **"Mejbaul Mubin"**। যদি সেই ইউজার লগইন করেন, তাহলে কোডটি ব্রাউজারে এই আউটপুট দেখাবে:

```html
<div>Mejbaul Mubin</div>
```

### বাস্তব উদাহরণ:

১. প্রথমে আপনাকে নিশ্চিত করতে হবে যে **অথেনটিকেশন সিস্টেম** সঠিকভাবে সেটআপ করা আছে (যেমন: লগইন সিস্টেম কাজ করছে)।  
২. ইউজার লগইন করলে `Auth::user()` সেই ইউজারের ডেটা রিটার্ন করবে।  
৩. আপনার Blade টেমপ্লেট ফাইলে এই কোড রাখুন এবং এটি পেজে ইউজারের নাম দেখাবে।

### যদি ইউজার লগইন না করেন?

যদি কোনো ইউজার লগইন না করে পেজটি দেখতে চান, তাহলে `Auth::user()` **null** রিটার্ন করবে।  
এর জন্য আপনাকে চেক করতে হবে:

```php
@if(Auth::check())
    <div>{{ Auth::user()->name }}</div>
@else
    <div>Guest</div>
@endif
```
